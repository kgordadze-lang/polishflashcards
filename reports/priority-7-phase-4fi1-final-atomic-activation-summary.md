### Why revision 1, derived and not chosen

`freeze_editorial` accepts a `previous` frozen baseline or none. No prior
frozen Priority 7 envelope is retained anywhere in this repository — the only
`*frozen*.json` on disk is `reports/priority-5-forward-frozen-baseline.json`,
which belongs to Priority 5. With `previous=None` the tooling admits exactly
one value: asking for revision 2 raises `FROZEN_INITIAL_REVISION`, and 0 or
negative raises `FROZEN_REVISION`. Revision 1 is therefore derived, not picked.
The I1 suite asserts the refusals as well as the acceptance.

### The old G1/G2 digest is obsolete

`4a42cd6a15b5a52246484aa82bbbf214b3525b88ea11756b0fac937793606671` is the
Phase 4F-G1 projection of the **pre-H2, 29-example** corpus. It was recorded in
`reports/priority-7-phase-4fg1-freeze-manifest.json` and deliberately never
materialised. It is not targeted here, and the I1 suite asserts the released
bytes are **not** those bytes.

There is no Phase 4F-G2 in this repository — no `test_priority7_phase4fg2.py`,
no G2 report, no parked G2 candidate. The "G2 architecture" was reconstructed
from the live repository instead: the Phase 3F-A atomic guard, the G1 freeze

## 4. Loader activation

One call site, in the Priority 7 block of `index.html`, through the existing
shipping consumer in `pp-verb-patterns.js` — which is **byte-identical to the
baseline**. No second parser or renderer was created.

```js
const PRIORITY7_RUNTIME_URL = "./content/verb-patterns.json";
function pSettleRuntime(accepted){
  if(accepted !== true) return;
  if($("home").classList.contains("active")) renderTopics();
  if($("patterns").classList.contains("active") && P.view === "index") pRenderIndex(false);
}
void PP_VERB_PATTERNS.loadRuntimeDocument(
  (url, options)=> fetch(url, options), PRIORITY7_RUNTIME_URL
).then(pSettleRuntime, ()=>{});
```

* `loadRuntimeDocument` appears **once** in the shell; `content/verb-patterns.json`
  appears **once**; `fetch(` goes 2 → 3.
* `fetch` is wrapped rather than passed by reference, because a bare `fetch`
  loses its binding in a browser.
* **Failure is non-blocking and silent.** Offline, a missing file, an HTTP
  error, an unparseable body or a document failing the closed public-shape
  check all settle to `false`; the neutral unavailable state stays exactly
  where it was and the rest of startup is untouched. Both promise legs have a
  rejection handler.
* No preview, fixture, editorial-file or query-switch alternative exists.
  `URLSearchParams`, `searchParams`, `?fixture`, `loadFixture`,
  `__acceptForTest`, `localStorage` and `location` are all absent from the
  activation block.
* On success only what is already on screen is refreshed — the topic tile's
  count, and the index if the learner is standing on the unavailable state.
  Nothing is persisted, nothing navigates, no focus moves.

## 12. Historical test handling

I1 legitimately supersedes claims of the form *the runtime file is absent*,
*the loader is dormant*, *`APP_VERSION` is 8.10*, *the cache is v65*, *no
shipping P7 activation exists*. Two distinct treatments, following the
repository's established practice:

**Live release/activation suites — updated to the real I1 state.** Every
assertion stays an exact pin, so nothing is hidden:
`tests/test_phase2c_navigation.js`, `tests/test_phase3_closeout.js`,
`tests/test_phase3b_focus_scroll.js`, `tests/test_phase3b_mobile_layout.js`,
`tests/test_phase4b1_service_worker_cache.js`,
`tests/test_phase4b2_offline_navigation_installability.js`,
`tests/test_phase4b3_audio_resilience_range_storage.js`,
`tests/test_priority7_release_loader.js`, `tests/test_priority7_patterns_ui.js`,
`tests/test_priority7_choose_ui.js`, `tests/test_priority7_phase5a_bridge.js`,
`tests/test_build_pages.py` (its `APP_VERSION` pin exists to be a one-line
bump). This mirrors how commit `f6bdc73` handled v64 → v65 and 8.09 → 8.10.

**Historical Python phase suites — restated over a closed, phase-owned
normaliser**, `tests/priority7_phase4fi1_normalizer.py`, exactly as the
E1/F2/H2/H2.1/H3 layers already work. The shell now carries the I1 layer on top
of the H3 layer, so suites strip I1 first and H3 second.

### The normaliser is all-or-nothing by construction

There is **no way** to obtain a normalised byte without first building a
`Phase4FI1Bundle` over all three core components together. `I1.bundle(...)`
raises unless the layer is uniformly `absent` or uniformly `complete` across
both pinned `index.html` edits, all six pinned `sw.js` edits, and the runtime
file — which must be present with exactly the pinned SHA-256 **and** byte
length, or absent altogether.

It therefore cannot hide any of: different runtime bytes (checked by digest,
not substitution); a wrong revision; a missing or extra runtime; a missing,
duplicated or differently-URL'd loader activation; a preview/fixture URL; a
wrong `APP_VERSION`, a future version bump, a wrong or future cache generation;
a missing service-worker required asset; a wrong classification; any unrelated
`index.html` or `sw.js` edit; an H3 wording regression; recognition-only
semantics; content, governance or audio mutation; or an arbitrary
generated-page change — generated pages are admitted only by their single
footer stamp, and the sitemap only by `<lastmod>` values with an identical URL
set, order and structure.

Section 9 of `tests/test_priority7_phase4fi1.py` proves each of those refusals
individually.

**No behavioural assertion was weakened, no suite was skipped, deleted or
marked expected-failure, and the Phase 3F-A atomic guard runs against the live
I1 state.**
