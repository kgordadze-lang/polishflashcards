## 3. Risk of the recommendations themselves being mistaken for approval
**HUMAN DECISION REQUIRED** (procedural risk, not a code risk). Because this analysis is thorough and includes concrete field names, enum values, and exact code-line references, a future author could mistake "recommended option" for "approved architecture" and begin implementing Option A2/B1/C1/D2 without an explicit Phase 4A2-2 sign-off. The decision-summary document's closing line addresses this directly ("Nothing in this document authorizes Phase 4B authoring, ID allocation, or any schema/runtime change") but the risk is inherent to producing detailed, implementation-shaped recommendations in a reports-only phase, and is recorded here so the independent reviewer is aware of it.

## 4. formatVersion recommendation risk
**HUMAN DECISION REQUIRED.** This analysis recommends `formatVersion` increments for Decisions A and B (new optional lemma fields, new `clauseKind` enum value) on the grounds that both validators are closed-schema and reject unrecognized shape outright. This is a defensible reading of the project's own stated `formatVersion` semantics ("incompatible data-contract semantics") but is itself a judgment call this audit makes, not a pre-existing documented rule — `formatVersion` has never moved in this system's history, so there is no precedent instance to confirm the rule against. The human reviewer should explicitly confirm or override this judgment before Phase 4B, since it has downstream consequences for every consumer that pins to `FORMAT_VERSION = 1` today (including any cached service-worker-served JS bundle, per the pipeline map's `sw.js` observation).

## 5. Stable-ID lifecycle interpretation risk
**HUMAN DECISION REQUIRED**, restated from the stable-ID lifecycle report §2: handoff constraint #12 ("allocate no stable ID until the exact Phase 4 editorial record is approved") is a single unqualified sentence that does not itself distinguish lemma IDs (which need no key and are already determined by frozen lemma text) from meaning/pattern/example IDs (which need author-chosen keys that don't exist until drafting). This analysis adopts the strictest reading (Option C1: defer all four ID kinds) as the safe default, per the instruction not to recommend a workaround that falsifies the freeze — but this is an interpretation, not a re-statement of an already-explicit rule, and the human reviewer should confirm it is the intended reading.

## 6. Metadata-only aspect partner recommendation carries an unresolved product question
**OBSERVED FACT**, restated from the metadata-aspect-options report §5: Option A2 (recommended) makes `zaczynać`/`przeczytać` mentionable only from their anchor's card, not independently searchable/landable in the learner UI, because no lemma record is ever created for them under A2. This is a deliberate consequence of satisfying "no separate Phase 4 full-pattern record" as literally as possible, but it is a real product-facing limitation the human reviewer may not expect from the phrase "metadata-only aspect partner," and is flagged explicitly as its own sub-decision rather than folded silently into the main recommendation.

## 7. Direct-speech linguistic-fidelity tradeoff
**OBSERVED FACT.** The recommended Option B1 (add `direct-speech` to `CLAUSE_KINDS`) is the smallest and most schema-compatible option, but it does carry a genuine linguistic-fidelity compromise: the other three `clauseKind` values are all subordinating-conjunction-introduced embedded clauses, while direct speech is a quoted independent utterance with no subordinator. This analysis judges the mechanical/structural fit (same complement slot, same rendering shape, same validation shape) to outweigh the naming imprecision, but this is a linguistic judgment call the human reviewer — not this audit — should have final say over, since the task brief specifically asks for a "truthful" architecture, and truthfulness here is a matter of degree, not a binary pass/fail.

## 8. Required-lexical-material and 21-constraint recommendations are new proposals, not observations
**HUMAN DECISION REQUIRED.** Unlike Decisions A/B/C, which resolve gaps the Phase 4A-1 audits already identified and classified, the Option L2 (private lexical-material field) and the private authoring-manifest mechanism for the 21 constraints are **new proposals** introduced in this phase — they were not present in any Phase 4A-1 report as a named option. They are recommended because the task brief explicitly asked this phase to treat the lexical-material gap as a "fourth architecture decision" if unsupported (confirmed unsupported) and to recommend a preservation mechanism for the 21 constraints, but the human reviewer should weigh them with the awareness that no prior-phase audit vetted these two specific proposals independently.
